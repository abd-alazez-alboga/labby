# Live behaviour matrix: RIDE (on-demand booking and ride lifecycle, rider + driver apps)

**Area:** RIDE. It covers on-demand booking (map pin, saved places, stops, service types, estimate, matching toggles), dispatch and offers, accept, arrive geofence, wait grace, start, in-ride route changes, live tracking with route and ETA, connection lost, completion with metered fare and cash confirm, rider and driver cancellations, no_driver_found and retry, heatmap, online/offline, stale GPS, resilience, races and double taps.
**Out of area (owned elsewhere, referenced only):** wallet, mixed and receipt numbers, tips, promos, carried fees (MONEY-GROWTH); chat, SOS, share, rating and push tap routing (TRUST-COMMS); scheduled and shared rides (SCHED-SHARED); account-state gates and suspension (AUTH); admin ride pages (ADMIN); balance floor and earnings (DRIVER-OPS); V1 finding retests as such (V1-RETEST-XCUT). Ride-flow V1 findings H9, W20, W26, W32, W40 are still exercised here, because the screens that show them are ride screens.

**Sources read:** docs/SRS.md 4.4 (RIDE-01..08), TRK-01..04, PRC-01..04, PAY-02, DRV-05, DRV-09, NFR-A3, NFR-P2/P3, NFR-I1/I2, NFR-U2; docs/use-cases/rider.md (UC-R-01..09) and driver.md (UC-D-04, 06..10, 14); docs/milestones/M06, M07 (T1..T6 ACs, milestone criteria), M09 (T1..T3 ACs), README.md (V1 fix notes, owner rulings 2026-10-20/21: W40 ETA notice at +5 min, max once per 5 min; vehicle photo on full card before pickup only; zero-total "Nothing to collect"); backend/docs/api/rides-v1.yaml (transition table 1..11, booking validation, dispatch, re-dispatch, cancellation fee, retry, route change, tracing/metering, realtime events, push catalog, error codes), realtime-v1.yaml (availability, streaming, stale 30 s, WS protocol, close codes), surge-v1.yaml (heatmap levels and refresh); backend application.yml (env overrides); DevRegionSeeder, DevRideSimulator, NotificationRenderer (push copy); backend/docs/SEEDING.md; docs/design/canvas/README.md (board names); docs/reviews/review-V1-conformance-2026-10-20.md (rides-core, dispatch-realtime, live-run notes, H9, W20, W26, W32, W39, W40); app code: rider screens/ride/* (booking-screen, route-planner, pin-picker, ride-view, cancel-sheet, change-route, surge-changed-sheet, saved-places, ride-preferences, ride-history), ride/ride-errors.ts, i18n/ride-translations.ts, home-screen, region strings; driver components/ride/* (offer-card, ride-sheets, complete-screen, cancel-sheet), rides/DriverRideProvider.tsx, rides/format.ts, heatmap/levels.ts, i18n/translations/en.json + ar.json (ride.*, heatmap.*, availability.*).

**Conventions used in the rows**
- Accounts (password `Password1!`, password login only, never OTP): **R1** = +963900000001 (rider, EN), **R3** = +963900000003 (rider), **D5** = +963900000005 (driver; Economy+Comfort; app defaults to AR); this is the account clicked in the driver app on the emulator. **D2** = +963900000002 (Economy), **D6** = +963900000006 (Comfort), **D7** = +963900000007 (Economy+Family, 7 seats). D2/D6/D7 are harness drivers.
- **Base setup (all rows):** backend in the dev profile with `RIDE_SIM_ENABLED=false` (rows that need the simulator say so); demo region **Damascus** as seeded (currency SYP; cancellation grace **5 min**, fee **5,000**; wait grace **5 min**, **500/min**; pickup fee beyond **10 km** at **1,000/km**; surge cap 2.0; Economy base 10,000, 2,000/km, 300/min, min 15,000; Comfort 15,000/3,000/450/min 22,500; Family 20,000/4,000/600/min 30,000; Morning rush 07:00-09:30 Sun-Thu +25%; zones City Center, Mazzeh, Old City, steps >=2 -> 1.2x, >=3 -> 1.5x, >=5 -> 2.0x). These per-region values are what the live test expects. The SRS defaults (grace 2 min, fee 2) are covered in RIDE-142. Before each row: `H cleanup` (cancel any active ride for the accounts in use; all harness drivers offline).
- **H** = python harness, using the same REST/WS endpoints the apps use. `H-drv Dx @P` = log in Dx, `PUT /driver/availability` online, open `/api/v1/realtime`, stream a location every 5 s at point P (or along a path). `H-rider Rx book A->B [type]` = `POST /rides/estimate` then `POST /rides`. The harness answers offers with `POST /driver/offers/{id}/accept or decline` and drives lifecycle with arrive/start/complete/cash-confirm.
- **GEO P** = `adb emu geo fix <lng> <lat>` on the emulator (feeds whichever app is open). Points: **PU** 33.5120,36.3000 (City Center zone); **DST** 33.5000,36.2400 (Mazzeh zone); **OLD** 33.5100,36.3350 (Old City zone); **MID** 33.5300,36.2700 (no zone); **FAR** 33.4600,36.2000 (in region, about 13.7 km straight line from OLD); **OUT** 34.7300,36.7100 (Homs, no region).
- "Clicked: rider app" means the emulator runs the rider app and the driver is the harness. "Clicked: driver app" is the reverse. Two-party behaviours have one row per side.
- Money format: EN "SYP 5,000", AR "⁦5,000⁩ ل.س" (Western digits, LTR isolate, ل.س label, NFR-I2 / W20).
- OTP: no RIDE row consumes an OTP. All rows use seeded password accounts, so the OTP column is "-" throughout and the owner numbers A/B are not spent here.
