**Shorthand used in the table**
- Owner phones (REAL SMS): **A** = `0991877688` -> `+963991877688` (rider), **B** = `0935218431` -> `+963935218431` (driver). Pa / Pb = passwords the tester sets for A / B.
- Seeded FAKE phones (password `Password1!` = **P**, never OTP): **R1** `+963900000001` rider · **D2** `+963900000002` rider+driver · **R3** `+963900000003` rider only (driver gate) · **SA** `+963900000004` Super Admin (admin role only) · **D5** `+963900000005` driver سامر · **D6** `+963900000006` driver ليلى (insurance near expiry) · **D7** `+963900000007`. Fake unregistered numbers used only where NO SMS can be sent (refused before send, or gateway down): `0900000066/77/88/98/99`.
- **Harness** = python API client on the same endpoints the apps use; admin actions through the harness log in as SA. "costs A x1" = one real code consumed from A's hourly budget.
- **OTP budget (AUTH-04):** 5 codes per phone per hour across ALL purposes, 60 s cooldown per phone+purpose, 5-min expiry, 5 wrong attempts per code. A-rows cost ~40 codes and B-rows ~17 codes in total, so the run needs ~8 A-hours / ~4 B-hours of budget: batch the rows by hour, or (allowed DB step, the UI cannot reach a fresh budget in reasonable time) `DELETE FROM otp_codes WHERE phone='+963991877688'` between batches. Rows marked DESTRUCTIVE-last lock a code or exhaust the hourly cap and go at the end of each phone's run.
- **Ordering constraints:** (1) A registers in the rider app before any signed-in A row; (2) the A->B->A phone-change rows run while B is still unregistered, i.e. before the driver registration of B; (3) delete/reactivate rows for A run after the 2FA rows; (4) the "New admin, new phone" row with B runs last (B becomes admin-only) or B's user row is removed by DB afterwards.
- Env overrides used (only where waiting is unreasonable): `LOGIN_THROTTLE_WINDOW_SECONDS=120`, `JWT_ACCESS_TTL_SECONDS=60`, `SMS_GATEWAY_URL=http://127.0.0.1:9` (gateway-down rows; restore after).
