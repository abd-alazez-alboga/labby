**Setup macros used in the table**
- `SIM-OFF`: backend dev profile with `RIDE_SIM_ENABLED=false`, so no seeded driver moves by itself. Emulator time zone = Asia/Damascus unless a row says otherwise.
- `H-ONLINE(Dx)`: python harness logs in Dx, goes online and streams GPS near the pickup every 5 s (same endpoints as the driver app).
- `H-WIN(Dx, days, from-to)`: harness `PUT /api/v1/driver/availability-windows` for Dx (the UI path itself is owned by DRIVER-OPS).
- `FAST-S`: ADM -> Regions -> Damascus -> Scheduled rides: reminderFirstMin 30, reminderSecondMin 25, fallbackLeadMin 20, minLeadMin 30 -> Save (valid: 30 > 25 > 20, 30 > 20). A ride booked in the UI for now+31 min then gets tier-1 at ~+1 min, tier-2 at ~+6 min, conversion/fallback at ~+11 min. Restore (blank = defaults 1440/60/15/30) after the block. Note the rider app copy hard-codes 30 / 15 min (I18), so it will still say 15 under FAST-S.
- `SHIFT-S(t)`: SQL `UPDATE scheduled_rides SET scheduled_at = now() + interval 't' WHERE ride_id = :id;` (clock job runs every 30 s). Used only to reach T - lead quickly.
- `SHIFT-DEP(t)` / `SHIFT-EXP(t)`: SQL `UPDATE shared_rides SET departure_at|expires_at = now() + interval 't' WHERE ride_id = :id;`.
- `FLOOR(Dx)`: DB-insert a driver_ledger debit (or complete cash rides) so Dx's balance is at/below -500,000 SYP; `UNFLOOR` = ADM records a settlement above the floor.
- `GATHER(n)`: harness creates/joins a gathering shared ride so it holds n parties (creator first).
- Unless stated, rides are inside Damascus City Center, Economy, cash.
