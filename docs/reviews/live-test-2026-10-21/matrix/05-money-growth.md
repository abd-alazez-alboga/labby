**Conventions used in Setup:**
- R1 = rider +963900000001 (rider app on the emulator unless the row says harness); R3 = rider +963900000003 (usually harness rider); D5 = driver +963900000005 (driver app on the emulator, Economy + Comfort); D6/D7 = drivers +963900000006/7 driven by the python harness (start backend with RIDE_SIM_ENABLED=false so the harness owns them); ADM = Super Admin +963900000004 in a browser at 1440 px. All fake phones: password `Password1!`, never OTP.
- Damascus (dev seed): currency SYP; Economy base 10,000 + 2,000/km + 300/min, minimum 15,000; cancellation grace 5 min / fee 5,000; wait grace 5 min then 500/min; pickup fee beyond 10 km at 1,000/km; commission 25 / 20 (>100) / 15 (>200) weekly trips; morning-rush surcharge +25% 07:00-09:30 Sun-Thu.
- "GS" growth settings (no admin UI, M13 G3): set by the harness through the admin region-bundle PUT: referrer 5,000 / referee 5,000, 0.01 point per SYP, redeem from 500 points at SYP 10 per point. Code defaults when null: 5 / 5, 1 pt per unit, 100 pts at 0.05.
- Promo catalog codes (SAVE20, FIX3000, BIG, FIRST50, FIRST10, CAP1, ONCE, FUTURE, COMFORT10, USDONLY, DEAD) are created in MONY row "[Promo] Setup promo catalog"; region QA-USD (currency USD) is created by the harness for currency-isolation rows.
- Expected amounts use the stored values: T = stored fares.total; commission = HALF_UP 2 dp of T x weekly rate. SYP renders without decimals, EN "SYP 25,000", AR "25,000 ل.س" (LTR-isolated, Western digits).
- OTP: only the referral registration rows use owner phone A (0991877688, rider). Run "[Referral] Register with unknown code" and "…R1's code" in one registration session (one code). The reactivation row consumes 2 more codes on A and soft-deletes A, so it runs last.
- DB edits are used only to reach a state (moving accepted_at / arrived_at / completed_at, setting points balances, ending a challenge window, inserting a fake referee). The behaviour itself is always clicked.
