- **Env baseline E0:** backend dev profile, `FIREBASE_CREDENTIALS_PATH` set (real FCM), `RIDE_SIM_ENABLED=false`, `PUBLIC_BASE_URL=http://10.0.2.2:8080` (share links open on the emulator), `NOTIFICATIONS_DISPATCH_CRON` default 5 s. Emulator = Google-Play image, mock location inside Damascus (region emergency number 112). Admin = desktop Chrome at 1440 px with browser notifications allowed. **Never press the call key in the dialer** (112 is a real emergency number; seeded numbers are fake).
- **R-app** = rider app clicked on the emulator; **D-app** = driver app clicked on the emulator; **H-D** = python driver harness (login, go online, stream GPS every 5 s, accept offer, GPS within 100 m + arrive, start, complete, cash-confirm, WS `chat.send` / `chat.read`); **H-R** = python rider harness (POST /rides estimate+book, cancel, WS chat, rate, report, lost-item, tickets).
- **RIDE(state)** = one on-demand Economy ride R1 to D5 brought to `accepted` / `driver_arrived` / `in_progress` / `completed` (cash) by the app under test + the harness for the other party.
- **DB-AGE(ride, d)** = `UPDATE rides SET completed_at = completed_at - d` (or `cancelled_at`) and `UPDATE chat_threads SET closed_at = <terminal> + interval '24 hours'` for that ride. Allowed only because 24 h / 7 d / 90 d windows cannot be waited out live.
- **SNAP** = env `TRUST_RATING_SNAPSHOT_CRON='0 */1 * * * *'` (snapshot + threshold job every minute) and backend restart; wait 70 s after the last rating. **RATINGS(n, score, user/role)** = harness loop of n completed rides with the given scores (preferred for n <= 10), else DB insert of n completed rides + `ratings` rows (unique ride x rater_role).
- **CAT** = two admin-created ticket categories from S0: "Payments / المدفوعات" (default priority high) and "App problem / مشكلة في التطبيق" (normal). **HELP** = one help category "Rides / الرحلات" with 2 published EN+AR articles ("How fares work / كيف تُحسب الأجرة", "Cancelling a ride / إلغاء رحلة") + 1 draft.
