## Observed transient (not reproduced)

- Right after switching the rider app to Arabic **live**, the first ride screen drew the link
  "الإبلاغ عن عمر" as "الإبلاغ عن" (Android measured the label before the Arabic font/direction
  settled). It rendered correctly on every later render and on a cold start (`rider-ride-ar.jpg`),
  so no code change was made; worth a glance on a real device.
- The rider dev build on the emulator predated M13 (missing the `expo-clipboard` native module)
  and was rebuilt locally (`./gradlew app:installDebug`) before the pass.

## Known, accepted (not app strings)

- **Data entered in one language** shows as entered (e.g. the region name "Damascus", test names
  "Dev Rider", the vehicle colour "Grey"): content, not UI copy.
- **Browser-native date inputs** render their placeholder (`mm/dd/yyyy`) in the browser's own
  locale; the app cannot translate them.
- **Server error messages are English-only** (no `Accept-Language` handling server-side). The apps
  show localized copy instead: the rider profile screen no longer shows the raw message (fixed in
  this ticket); the admin surge override shows the server detail line in the English UI only.

## Automated checks wired into each gate (zero missing keys)

- Admin `src/test/i18n-keys.test.ts`, rider `src/i18n/__tests__/i18n-keys.test.ts`, driver
  `src/__tests__/i18n-keys.test.ts` — run by each app's `npm run check` and CI: every literal
  `t('…')` key exists in EN and AR, template-key prefixes name real keys, no empty strings, AR
  placeholders match EN (Arabic plural forms may drop the number), no Arabic-Indic digits.
- Backend: every notification event renders EN + AR (`NotificationRendererTest`), SMS digits are
  pinned to `Locale.ROOT` (`OtpServiceImplTest`).
